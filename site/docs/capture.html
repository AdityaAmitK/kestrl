Capture traffic

Capture means Kestrl observes requests made by another app or process. It differs from send, where Kestrl makes the request. Live captures stay in memory unless you save them to history.

iOS Simulator and Android emulator

Device capture routes HTTP and HTTPS through Kestrl's local interception proxy. Start a capture with one booted simulator or emulator.

kestrl capture sim
kestrl capture android

Android capture supports exactly one booted emulator and does not support physical devices. Before changing its global http_proxy setting, Kestrl saves the previous value in a private record. It restores that value when capture stops or on the next device capture start. If the emulator is no longer running, Kestrl keeps the saved record and reports an error rather than discarding it.

Browser capture

Kestrl opens a separate Chromium-family browser window with an isolated temporary profile. Supported browser names are chrome, arc, brave, edge, chromium and helium.

kestrl capture browser --browser helium --url http://localhost:3000

Port capture

Port capture observes plain HTTP on a local loopback port, for example a server listening on port 1337. On macOS it reads lo0 through Berkeley Packet Filter (BPF) and reconstructs complete TCP/HTTP exchanges.

kestrl capture port 1337
kestrl capture port status
kestrl capture port setup
kestrl capture port uninstall

One-time BPF setup

Opening BPF requires administrator authorization. kestrl capture port setup prints the setup plan; it does not run the privileged installer. From a checkout, the user can install it explicitly:

sudo sh scripts/kestrl-bpf.sh install --user <name>

The installer creates a dedicated kestrl_bpf group, adds the named local user, installs a root-owned script at a fixed path and loads a LaunchDaemon that grants the group access to /dev/bpf* at boot. It refuses to run if Wireshark's ChmodBPF is installed. Kestrl's capture filter limits what Kestrl reads; members of the group can read every interface through BPF, not only loopback. The group permission is broader than Kestrl's own capture scope.

The setup does not run automatically from the CLI. It uses no setuid binary or signed helper. status reports whether BPF is available and setup is installed. uninstall prints the removal command; removal targets Kestrl's membership, daemon, script, group and the device permissions it assigned.

Certificate trust

HTTPS interception requires the Kestrl root certificate to be trusted by the captured device or simulator. The proxy CA is local to this machine. Use proxy ca to show its file path and fingerprint, and proxy trust to install or stage trust for a supported device.

kestrl proxy ca
kestrl proxy trust --sim
kestrl proxy trust --android

Excluded HTTPS hosts tunnel through without capture or history entries. Device capture supports HTTP and HTTPS through the Kestrl CA; pinned TLS connections may reject interception.

System proxy safety

The interception proxy binds to loopback. Kestrl saves the macOS system proxy state before changing it and restores it when capture exits. If capture is interrupted or the process crashes, the next start attempts recovery.

Run kestrl proxy restore to restore saved macOS and Android emulator proxy settings after an interrupted capture. Restore retries keep the saved state until every saved service has been restored. Android proxy state is retained if the emulator is not available for restoration.

When capture stops unexpectedly: run kestrl proxy restore, then check your system or emulator proxy settings before starting another capture.

Capture limits

  • Only one device capture can run at a time across CLI and app.
  • Android device capture requires exactly one booted emulator; physical devices are unsupported.
  • Capture data is held in memory while active. Use --save to save exchanges to history.
  • Host filters accept domains and whole-hostname * patterns. A plain domain includes itself and its subdomains at a dot boundary.
