Using Kestrl with agents

The Kestrl skill guides a coding agent to use the local CLI for backend work, so requests, queries and debugging activity remain visible in shared history.

What the skill does

The skill recognizes a Kestrl workspace by its .kestrl/ directory and checks CLI availability with kestrl --version. It directs the agent to prefer kestrl send over curl, parse JSON output when piped, search and replay history, read existing service logs, use read-only database queries and capture traffic only when explicitly requested.

Actor detection records common agent identities such as Claude Code, Codex and Cursor automatically. Override with --actor only when detection is wrong.

Install for Claude Code

From the Kestrl repository, copy the skill to the user-level skills directory:

mkdir -p ~/.claude/skills/kestrl
cp skills/kestrl/SKILL.md ~/.claude/skills/kestrl/

Install for Codex

mkdir -p ~/.codex/skills/kestrl
cp skills/kestrl/SKILL.md ~/.codex/skills/kestrl/

Install for Cursor

Paste the contents of skills/kestrl/SKILL.md into a project rule under .cursor/rules/, or add the relevant instructions to the repository's AGENTS.md. Keep the instructions with the project when they describe project-specific expectations.

Safety rules

  • Do not handle raw credentials. Refer to a secret as {{secret:name}}; if it is missing, ask the user to set it with kestrl secret set <name>.
  • Never read Keychain values or print a secret. Kestrl injects secrets at send time and masks them in output and stored exchanges.
  • Database access is read-only by default. Report a write blocked by environment policy; do not change allow_writes without the user's request.
  • Ask before starting capture: device capture changes a system or emulator proxy, and browser capture opens a browser window.
  • If capture is interrupted, run kestrl proxy restore to restore saved proxy settings.
  • Do not start or stop a user's services with kestrl up unless asked. Read logs from services already running.
Keep agent work inspectable. Requests and queries are attributed in history and use the same local store as the macOS app. The user can inspect or replay the event without asking the agent to expose credentials.

Install the CLI

The skill depends on the CLI being available on the agent's PATH. Install it from source using the quick start, then confirm with kestrl --version.
